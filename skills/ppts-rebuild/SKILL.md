# 参考图重建线（super-ppts-rebuild）

用户给出一张截图 / 参考图（幻灯片照片、设计稿、旧 PPT 截图），要求
「复刻 / 还原 / 做成可编辑」。你的职责：把它重建为**原生可编辑**的 PPTX 页，
而不是把图片贴进幻灯片——贴图是底线违例，重建的意义就是可编辑。

引擎与环境与 PPTX 交付线完全同源（pptx-designer；`ppts_check` 自检、
`validate_pptx.py` 机检、渲染验收），本文件只讲重建特有的流程与标准。
颜色/字体纪律沿用 [../shared/design-tokens.md](../shared/design-tokens.md)
（含 CJK 排版红线）。

## 工作流（四步，交付级不得跳步）

### 1. 参考图盘点（看图清点，先出清单再动手）

对参考图产出**元素清单**（给用户过目）：

| 类别 | 盘点内容 | 重建策略 |
|---|---|---|
| 文本 | 每段文字内容、层级（标题/正文/角注）、对齐、颜色 | 原生文本框，逐字转录（看不清处标 `[?]` 问用户） |
| 几何图形 | 矩形/圆角/线条/箭头/流程框 | 原生形状重绘（rect/rrect/arrow…） |
| 图标/简单装饰 | 线性图标、简单徽标形状 | 原生形状或内联 SVG 重绘；**复杂品牌 logo → 裁剪原图嵌入**并告知用户 |
| 照片/复杂插画 | 位图内容 | 从参考图**裁剪原图**嵌入（`cover_image()` / add_picture） |
| 图表 | 柱/条/饼/折线 | **原生图表组件重建**（能编辑数据），数值从图中读取，读不准标估算 |
| 版式 | 栅格、安全边距、分栏、对齐基线 | 记录英寸坐标估算（按 16:9 13.33×7.5in 反推） |

同时记录整页配色（背景/主色/强调色，取色说明写进清单）。

### 2. 重建（Build Mode 生成脚本）

- 写 Build Mode 生成脚本（同 PPTX 线），按清单逐元素放置；
- **先做单页**；用户给了多页截图时逐页重建并询问是否合并成一份；
- 文本转录不确定的一律 `[?]` 占位并在交付时列出——**不得编造看不清的文字**；
- 位图裁剪用 Pillow（pptx-designer 环境自带）从参考图裁出后保存为素材文件，
  脚本里引用相对路径（可复现纪律）。

### 3. 对比验收（并排对比 + 逐元素对账）

渲染 PNG 后**并排对比**（参考图 vs 渲染图），逐元素对账：

```text
Element audit: p1-kpi-card
Reference: 白底圆角卡片 (x=0.6in, y=2.1in, w=3.0in)，标题 16pt 深蓝
Rebuild:   一致（PASS）
---
Element audit: p2-chart
Reference: 6 根柱，3 月最高约 190
Rebuild:   5 根——3/4 月被合并（FAIL）
Action:    拆回 6 根，重渲。
```

- 状态 `PASS / NEEDS_REVISION / BLOCKED`，**最多三轮修订**（与上游
  visual-to-editable 同纪律）；三轮后仍有差异 → 如实列出残留差异交付；
- 对比维度优先级：**文字内容 > 结构/层级 > 版式位置 > 颜色 > 像素级相似**。
  用户要的是可编辑的同一页，不是像素复制品——颜色误差 ±10% 内可 PASS。

### 4. 交付

- 按交付包协议：`.pptx` + `.pdf` 双登记、`validate_pptx.py` 机检结论、
  渲染 PNG、逐元素对账表；
- 明确列出：哪些元素是裁剪嵌入的位图（不可编辑）、哪些文字是 `[?]` 占位、
  哪些数值是从图估算的——**重建的保真边界必须说清楚**。

## 红线

1. **禁整页贴图**：把参考图整张作为图片插入 = 交付无效；
2. 看不清的文字/数值不编造，标 `[?]` 或估算并标注；
3. 品牌 logo 与可识别人物：裁剪嵌入前需用户确认（同图片策略）；
4. 三轮修订封顶，残留差异如实列出，不静默交付。
