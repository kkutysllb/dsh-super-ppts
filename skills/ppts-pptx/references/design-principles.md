# 设计原则（PPTX 交付线）

这些原则定义本技能期望的设计判断力。它们是决策框架，不是逐条执行的清单——
冲突时以「受众能否更好地理解、感受、决策」为准绳。

## 设计师心态

- 从受众出发：他们必须理解什么、感受什么、决策什么？
- 克制优先于装饰。每个元素都必须挣得自己的位置。
- 把整套 deck 当作一个视觉系统，而不是一组互不相关的页面。
- 在尺度、密度、节奏、页面角色上使用**有意图的对比**。
- 一切设计选择都能用沟通意图解释，而不是「这样好看」。

## 内容规则

- 一页一个主论点。
- Hook 页副标题要短；把完整的行动陈述留给 CTA 页。
- 用具体论断与真实数据；示例与假设必须显式标注。
- 不使用填充式动词与空泛断言（「赋能」「领先」「一站式」「生态」「革命性」），
  除非用户明确提供了这些词。
- 六条以上要点通常需要拆两栏、卡片、表格或图示；**永远不要把长列表压缩成小字**。
- 密度刻意变化，但视觉系统保持锁定。
- 技术主题受益于代码 / 架构 / 规格 / 流程视图；教学主题受益于练习；
  证据密集主题需要来源标注与图注。
- 引用要短，署名完整（姓名、职务、机构）。

## 视觉反模式

- 每页都重复同一种卡片网格；
- 没有语义目的的装饰性渐变；
- 为塞下过多内容而缩小正文字号；
- 拉伸变形或与主题无关的图片；
- 没有明确结论或标签不可读的图表；
- 随机用色、片中途换主题；
- 用整页截图冒充可编辑内容；
- 指标造假精度（如给估算值标小数点后两位）；
- 把通用 hero/problem/features/CTA 套在科研、学术、临床素材上。

## 提案规则

一份方向提案只有当**页面架构、数据形态、封面处理、字号尺度或视觉语言**
发生变化时才是结构性的。只换色板的变体不算独立方案。

交付级任务且方向未锁定时，准备至多 3 个真正不同的方向，每个都要说明
受众契合、页面架构、视觉语言与代价。**不要生成三套完整 deck 只为了比颜色**。
用户已有明确方向时，直接按单一路线做页面规划。

## 量化护栏（预检默认值，不替代判断）

- 正文投影场景常规不低于 14pt；11pt 是图注/密集参考材料的下限，不是目标值。
- 每页一个主要结论；独立形状超过 ~50 个时，除非密度是有意图的且结果仍可读，
  否则视为超载。
- 字号层级通常 3-4 级足够；层级不需要时不要为装饰制造尺度变化。
- 重要内容保持一致的安全边距；**永远不要只靠动画、hover 或颜色**传达关键含义。
- 深色主题用近黑/近白端值，对比度在真实渲染 PNG 上检查。
- 高密度页之后跟一个呼吸页（叙事允许时）；相邻页结构重复需要有叙事理由。

## 动效与无障碍

动效必须有沟通目的。科研、学术、医疗、政务、印刷与无障碍敏感场景，
默认无动效或简单淡入，除非用户明确要求。受众未知时保持保守。
**每条重要信息在静态 PDF/PNG 导出中必须依然完整可理解。**

渲染 PNG 检查项：对比度、字体回退（含 CJK）、阅读顺序、图注清晰度、
投影可读性、图表脱离颜色是否仍可解读。

## 重设计协议

修订既有 deck 时，先记录必须保留的东西：页序、导航标签、logo、法律文本、
数据、品牌 token。再识别要保留的模式、要移除的模式，以及解决问题的
**最小现代化杠杆**。改变视觉结构时不得悄悄改变内容语义与品牌含义。
模板驱动的重设计走 VI Build（见 [review-and-delivery.md](review-and-delivery.md) 的 VI token）。

## 生成路径区分

`generate_ppt()` 是 FreeStyle 路径，话题 query 与结构化 `content` 字典只是
同一路径的两种输入形态。需要逐元素坐标、自定义页面架构、或目标渲染器
无法表达的可复现设计系统时，用 Build Mode（写生成脚本，见
[content-and-api.md](content-and-api.md)）。
