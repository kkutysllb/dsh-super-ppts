# dsh-super-ppts DSH 0.1.16-alpha.1 适配升级设计

- 日期：2026-09-15
- 状态：已确认（用户批准）
- 目标宿主：DSH 0.1.16-alpha.1（runtime 实测 0.1.6-alpha.1 构建，slot 契约一致）
- 版本：插件 1.2.1 → 1.3.0（含破坏性变更，minor + release note 迁移提示）

## 背景

DSH 升级到 0.1.16-alpha.1 后发生两件事：

1. 插件自构造的 Agent 预设模式失效。新版 `dsh-agent-presets` 以 `agent.cordis.yml` 组合
   （cordis plugin rows + isolate realm）挂载 per-session agent；插件目前把
   `presets/preset.yml` + `presets/agent.cordis.yml` 拷到
   `~/.dsh/.agent-presets/super-ppts/` 的自造预设不再被识别。
2. 新增原生 UI 能力：侧边栏「新会话」与「工作区」之间可加按钮（`sidebar.panellist`
   list slot，实测渲染位置在 newSession 之后、`sidebar.workspaces` 之前）；插件可经
   `main` keyed slot 构建自己的原生工作台界面。

## 目标 / 非目标

目标：

- 移除失效的预设安装模式，清理用户目录残留。
- 侧边栏按钮 + 原生工作台按方案 B 落地：工作台定位为「高频新建演示的结构化 Brief 入口」，
  不在面板内重复设置页的模板管理。
- 工作台产物进入 DSH Agent 链路：Brief 填入会话输入框，由用户确认后发送；Agent 经
  能力通告路由 → 技能线（super-ppts-pptx / super-ppts-html）→ 原生工具
  （ppts_check / ppts_render / ppts_templates）完成生成与验收。
- 设置页「演示文稿」菜单项及模板管理、偏好编辑功能保持不变。

非目标：

- 工作台内不做模板上传/删除/重命名（留在设置页）。
- 不做工作台多视图（新建/模板/最近项目，方案 C，留待后续）。
- 不改为「直接发送给 Agent」；默认动作是填入输入框、用户确认发送。

## 设计

### 1. 删除 Agent 预设模式（破坏性）

- `src/index.ts`：删除 `ensurePresetInstalled()` 及调用；`inject`
  （`['systemPrompt', 'tools', 'webServer']`）不变；systemPrompt 能力通告、三个原生工具、
  `/super-ppts` 路由全部保留。
- 删除 `presets/` 目录。
- 残留清理：apply 内 best-effort 删除 `~/.dsh/.agent-presets/super-ppts/`
  （目录为本插件专属创建，删除安全；失败静默跳过，不阻断加载）。
- README 去掉「切换演示文稿专家预设」引导，改为「直接在对话里说需求，能力通告会引导路由」。

### 2. 侧边栏入口（契约升级，位置不变）

- 保留 `sidebar.panellist`（id `super-ppts-panel`，order 100）+ `main` keyed
  工作台两段注册。按钮渲染在「新会话」与工作区列表之间；壳层拥有按钮、Tooltip、
  active 态，插件只出图标字形。
- `package.json` → `dsh.client.inject` 显式补上
  `@deepseek-ai/dsh-client-ui-conversation`（会话桥新增依赖，声明保证自足）。
- 旧宿主软探测保留：inject/register 抛错即静默跳过，设置页入口不受影响。

### 3. 工作台 → 输入框 → Agent 链路（核心新增）

替换现有「剪贴板 + 用户手动粘贴」桥（`sendToChat` v1），改为正式 API：

1. 定位会话：`sessions.list.getSnapshot().current`；无会话则
   `await sessions.create()` → `sessions.open(id)`（与「新会话」同宿主契约）。
2. 切回对话：`ctx.layout.selectPanel(null)`。
3. 填入草稿：`const actx = ctx.sessions.scope(id); actx.conversation.input.for(actx).setDraft(text)`。

依据（已核实源码）：新版 `SessionInputShell` 由 `inputHub.shellFor(binding)` 按 session
binding 构建，不依赖 composer 挂载，因此**工作台面板激活时也能直接写输入框**——这是旧版
被迫用剪贴板的原因，新版已消除。`setDraft` 是 `InputActions`/`SessionInput` 的正式
公开动作（persisted-draft seed 与程序化写入共用），caret 落在文末，随草稿持久化。

降级链：任一步抛错/服务不可达 → 回退现有剪贴板路径（v1 代码保留为 fallback），
面板内提示「已复制，请粘贴到对话」。发送动作由用户在输入框回车完成；busy 策略、
queue/steer 均走宿主既有提交面，本插件不触碰。

Agent 侧闭环不变：能力通告（SUPER_PPTS_GUIDANCE）→ 形态路由 → 技能 SKILL.md →
ppts_check / ppts_render / ppts_templates → present 产物回会话。工作台只做结构化
Brief（主题一句话 + 交付形态 + 模板选择），不是第二生成引擎。

### 4. 设置页与工程收尾

- 设置页 `settings.section`（id super-ppts）菜单项、Stateful 表单、
  `/super-ppts/api/*` 数据面一行不动。
- `src/client/index.ts` 类型参考与手写 `lib/client.js` 保持同构（新增 sendToChat v2、
  fallback v1）；继续遵守 `__ModuleLoader__.load` 自注册 bundle 形态。
- 版本 1.3.0；`release/` 新增说明，含「预设模式已移除」迁移提示。
- 冒烟测试更新：断言不再写 `~/.dsh/.agent-presets/super-ppts/`、新桥（conversation.input
  路径）存在、设置页路由仍注册。
- 工程红线不变：零 npm 依赖、execFile 参数数组、仅插件自有路由、不监听新端口。

## 数据流（升级后）

```
侧边栏按钮 ──► main keyed 工作台（Brief 表单 + 模板速览只读）
    │ 「放入输入框」
    ▼
sessions.current / create+open ──► layout.selectPanel(null) ──► conversation.input.for(actx).setDraft(text)
    │ 失败
    ▼ 剪贴板 fallback（v1）
用户在输入框确认 ──Enter──► Agent turn
    ──► 能力通告路由 ──► skills/ppts-pptx | skills/ppts-html
    ──► ppts_check / ppts_templates / ppts_render
    ──► 产物 present 回会话
```

## 失败模式与对策

| 场景 | 对策 |
|---|---|
| 无当前会话 | create + open（异步）；失败降级剪贴板 |
| `conversation.input` 服务不可达（旧宿主/未声明） | 降级剪贴板 v1 |
| `sessions.scope(id)` 返回 undefined | 降级剪贴板 v1 |
| 剪贴板也不可用 | 面板文案「请手动把提示词粘贴到对话」（现状） |
| 用户目录预设残留清理失败 | 静默跳过，不影响加载 |

## 验收

1. `npm run build && npm run smoke` 通过；smoke 含新断言。
2. 手动：点侧边栏按钮 → 填 Brief → 「放入输入框」→ 自动切回对话、输入框出现草稿 →
   用户回车 → Agent 按技能线执行并交付。
3. 无会话冷启动路径：工作台发起 → 自动建会话 → 草稿落框。
4. 降级路径：模拟服务不可达 → 剪贴板提示正常。
5. 升级残留：旧版本装的 `~/.dsh/.agent-presets/super-ppts/` 在新版本启动后被清理。
6. 设置页「演示文稿」菜单项、模板上传/管理/偏好编辑回归正常。
