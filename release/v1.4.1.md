## 修复

- **面板在真实宿主中渲染为无样式裸控件**（症状：任务面板的标签页 / 快速开始 /
  交付形态卡片 / 配置摘要全部呈浏览器默认样式，文本粘连成行）。1.4.0 的样式
  注入是单通道 `document.head.appendChild(<style>)`，在用户的 KCoder 环境
  中被静默吞掉（样式表字符串本身经校验合法、apply 时序正确、宿主包内无
  shadow DOM / iframe / 全局覆盖，根因落在该环境样式表通道被拦，无法从
  远端进一步取证）。
- 修复为**三通道 + 自检**：
  1. `adoptedStyleSheets`（构造样式表）：Chromium 下不受 `style-src` 限制，
     CSP 严格宿主里唯一可靠的程序化注入方式；
  2. `<style>` + 复制宿主 `csp-nonce` meta 的 nonce；
  3. 普通 `<style>`（无 CSP / 允许 unsafe-inline 的宿主兜底）。
  任一生效即可，全部幂等。
- **注入自检**：标签通道若被 CSP 拦截（cssRules=0）或三通道全部失效，
  面板顶部渲染红色警告条并 `console.error`——把静默故障变成可反馈的显性
  信息，不再让用户对着裸控件猜。
- 面板内容列限宽 `max-width:960px` 居中（此前在宽窗口下整行铺满、可读性差；
  不使用视口单位 / 固定定位，宽度与滚动仍归宿主）。

## 变更（视觉）

- 实机反馈「整体太素、浅色主题下选项卡选中态不可辨」——选中态与强调元素统一
  引入品牌蓝（`--sl-color-primary-*`，回退 `#3b5fd9`）：
  - 选项卡选中 = 品牌实底白字（hover 保持），未选中 hover 改淡品牌底；
  - 交付形态卡选中 = 浅品牌底 + 双层描边；
  - 快速开始 chip hover = 品牌色描边 + 文字；
  - 进度时间线 done = 品牌描边 + 序号圆点实底，当前阶段 = 品牌实底白字；
  - 产物类型徽标、面板标题左侧品牌竖条、主按钮 hover 深化一档。

## 兼容性与升级说明

- 自 1.4.0 直接升级无破坏性变更；样式注入对 1.4.0 之前正常生效的环境无行为
  差异（多通道冗余注入同一份样式表）。
- 若升级后面板仍显示红色警告条，说明宿主连构造样式表也拦截——请把开发者
  工具 Console 的红色报错反馈给插件作者。

## 验证

- `npm run build && npm run smoke` 全绿：**299 条断言 / 0 失败**（1.4.0 发布基线
  292 + 样式注入三通道 / 幂等 / nonce 拷贝 / 拦截检测 / 警告条 7 条）。
- 新断言全部经变异验证：砍 adopted 通道 → 注入与误报断言 FAIL；砍 nonce 拷贝
  → nonce 断言 FAIL；砍拦截判定 → 拦截与警告条断言 FAIL；还原全绿。
