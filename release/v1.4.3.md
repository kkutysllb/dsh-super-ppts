## 2. 新增

- 会话桥 v4（`sendToChatV4`）：按 0.1.7 契约重写会话投递链——
  - 当前会话判定改 `retainedBy.mainView` 口径（0.1.7 `SessionListState` 已删 `current` 字段）；
  - 新建会话选中改 `uiWorkspace.openSession(target)`（0.1.7 已删 `sessions.open`）；
  - 递送期经 `sessions.using(id, {source:'dsh-super-ppts'}, op)` 持引用（0.1.7 `scope(id)` 只借已 retain 的 generation）；
  - 输入壳解析对齐 `uiConversation.fillDraft` 口径（`conversation.input.for(actx)`），并新增**挂载重试**（6×200ms，openSession 后输入壳迟到位仍可送达）。
- `peerDependencies` 契约声明：`@deepseek-ai/dsh` + 四个 client 引擎包，范围 `>=0.1.0-rc.5 <0.2.0`（含 prerelease 比较器），全部 `peerDependenciesMeta.optional`——0.1.7 插件版本兼容门照常校验，安装面零副作用（实测见「兼容性」）。
- 冒烟新增契约层哨兵 7 项（死包 / inject 清单冻结 / peer 三则 / 版本号）与会话桥 v4 七断言（mainView 定位、openWorkspace(beforeOpen) 落点、挂载重试、using 持有期、无 submit 绝不报 submitted、create+openSession 路径），并保留旧宿主面回归 4 项。
- **模板缩略图**（dev 实测反馈）：上传时生成真实预览，两级兜底——
  ① 内嵌 `docProps/thumbnail.*` 提取（PowerPoint/WPS 保存的 pptx 自带，零进程成本）；
  ② 渲染链首屏兜底（soffice → pdf → pdftoppm 第 1 页，≤480px JPEG；python-pptx 等生成的 pptx 走这条）。
  清单新增 `thumb` 字段（`templates.list` 透传）；新增路由 `GET /super-ppts/templates/thumb/<id>`（信任围栏 + id 白名单防路径穿越 + 私有长缓存）；选择器用户卡渲染真图。删除模板同步清理缩略图。

## 3. 变更

- `dsh.client.inject` / `qilin.client.inject` 冻结为 4 个引擎包：`@deepseek-ai/dsh-client-locale` / `ui-slots` / `ui-conversation` / `ui-workspace`。
- 会话桥结果语义不变（`'submitted' | 'copied' | 'none'`），`createTaskAndStart` 相位逻辑不变（submitted → started/analyzing，其余 → waiting-launch 可重试）。
- 冒烟同构哨兵对子更新（`sendToChatV4` / `retainedBy` / `mainView` / `openSession` / `sessions.using`）；vm 沙箱补计时器（浏览器实况）。

## 4. 修复

- **「开始制作」在 0.1.7 宿主上恒降级剪贴板、从不自动提交**：
  - 症状：面板创建任务后提示「已复制创作提示词，请粘贴到对话发送」，任务停留在 waiting-launch，用户须手动粘贴回车。
  - 根因：0.1.7 契约层变更——`SessionListState.current` 字段删除（定位会话恒空）+ `sessions.open()` 删除（新建会话无法选中）+ `sessions.scope(id)` 收紧为已 retain 才可借代（写草稿链拿不到输入壳）。
  - 修后行为：v4 桥按 0.1.7 面（mainView 判定 / openWorkspace-beforeOpen / openSession / using 持引用 / fillDraft 同口径壳解析）恢复「落草稿 → 自动提交」闭环；旧宿主（≤0.1.6）面保留为软降级路径；任一步失败仍如实降级剪贴板，绝不假报 submitted。
- **设置页上传的模板在面板选择器「我的模板」里看不到**（dev 实测反馈，2026-09-25）：
  - 症状：设置页上传模板成功（列表可见、可设默认），但左侧栏面板的模板选择器「我的模板」分组/筛选里找不到新上传的模板。
  - 根因：模板库数据只在新建任务视图**挂载时取一次**；设置弹窗是 portal 覆盖层、面板一直保持挂载 → 上传后回到面板不重挂、不重取，选择器拿的是上传前的旧快照（host 存储侧无问题：registry 落盘与 `templates.list` 均正常，实证核对）。
  - 修后行为：**打开模板选择器即重取模板库**（`sp-tpl-open` 触发 `templates.list`），数据到达即刷新列表；挂载期预取保留（形态默认值需要）。
- **用户模板缩略占位在暗色主题下是一块「白板」**（dev 实测反馈截图）：
  - 症状：选择器里用户模板卡片的缩略图呈近白色矩形（白板），「默认」徽标暗底暗字看不清。
  - 根因：用户模板从未有真实预览（只有占位底），且占位底写死浅色渐变（`#EEF1F5→#D8DEE7`）不随主题；徽标用了在暗色主题解析成暗底的 `--dsw-alias-*` token。
  - 修后行为：真缩略图见「新增」；无图时占位走主题变量底；徽标改 accent 底 + 纯白字（与设置页 `.sp-badge` 同口径）。

## 6. 兼容性与升级说明

- **目标宿主**：DSH / KCoder **0.1.7-rc.2**（0.1.7 系列契约）；旧宿主（0.1.5–0.1.6）走双世代降级路径（`list.current` / `sessions.open` / `actx.conversation` 直读）。
- **契约声明**：manifest 新增 `peerDependencies`（`@deepseek-ai/dsh*` 五条，`>=0.1.0-rc.5 <0.2.0`）。0.1.7 起安装/启动按该范围强校验（不满足被拒，需精确版本豁免）；本插件声明覆盖 0.1.x 全系，**0.2.x 起会被门禁拒绝**（未验证大版本不默认放行）——届时随新版本平移范围。
- **peer 必须 optional 的实测依据**（2026-09-25，pnpm 11.23 最小复现）：非 optional 的宽范围 peer 会让 pnpm peer 自动安装解析到同 tuple 预发布 `0.1.0-rc.8`，把**整棵 448 包引擎树**静默拉进用户 profile；`peerDependenciesMeta.optional: true` 后零拉取（`.pnpm` 无 deepseek 条目），而兼容门只读 `peerDependencies` 不看 meta ⇒ 门禁照常、安装面零污染。冒烟把该形态钉成哨兵，防止回归成非 optional。
- **接口契约**：`ppts_*` 四工具、`/super-ppts/*` 路由信封、`ppts_task` 语义、设置页/模板库数据面**全部不变**；升级即替换包体（`dsh plugin add` / 手动更新），无需数据迁移。
- **slot 面**：`settings.section` / `sidebar.panellist` / `main` 三个注册与 0.1.7 槽位契约兼容（本轮仅注释/类型参考对齐，无行为改动）。
