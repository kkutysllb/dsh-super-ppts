# v1.0.1（2026-08-30）

## 版本信息

- 版本：1.0.1
- 日期：2026-08-30
- Tag：`v1.0.1`（功能提交 `2a4d19e`；tag 指向本版本发布提交）
- 发布渠道：npm registry（首发）+ GitHub 独立仓 + dsh-plugins 真源仓镜像

## 修复

- **`--check` 环境自检口径**：调用方解释器 < 3.10 但专属 venv 解释器满足要求时，不再误报 FAIL / NOT-READY——venv 满足则报 OK 并注明「生成将走 venv」，与 `resolve_python()` 的实际回落路径一致。此前在「系统 Python 3.9 + 专属 venv 3.14 可用」的机器上会给出误导性的 NOT-READY。
- FAIL 信息区分两种根因：专属 venv 缺失（附 venv 路径提示）与 venv 解释器同样过旧。

## 新增

- `venv_python_version()`：专属 venv 解释器版本探测（stdout / stderr 兜底）。
- `_version_tuple()`：版本字符串容错解析。
- `release/` 版本发布说明目录（本目录）：每版本一份，固定新增 / 变更 / 修复 / 删除 / 兼容性章节。
- npm registry 发布渠道：`dsh plugin --profile web add dsh-super-ppts`。

## 兼容性与升级说明

- 自检报告行前缀契约（OK / FAIL / WARN / MISS）不变。
- `ppts_check` 工具与 `--check` 的退出码在「venv 可用」机器上由 1 → 0（修正性行为变化：如实反映可用状态）。
- 升级方式：KCoder 插件管理检测到新版本后手动更新；或 `dsh plugin --profile web update dsh-super-ppts`（GitHub 直装用户）。

## 验证

- 四场景通过：venv 缺失 → FAIL（含路径提示）；venv 过旧 → FAIL（注明同样过旧）；venv 满足 → OK（注明走 venv）；端到端 `--check` → READY，exit=0。
